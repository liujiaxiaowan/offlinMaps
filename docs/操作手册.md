## 1. 项目概述

本服务将水经注下载并导出的 MBTiles 离线瓦片文件，统一发布为网络地图服务，供 Leaflet / OpenLayers / Cesium / QGIS 等前端或 GIS 客户端调用。

**核心特性：**

- **多源统一发布**：单个服务实例同时承载多份 MBTiles，通过 `mapId` 路径区分，无需每个文件单独部署
- **统一瓦片接口**：`/api/maps/tiles/{z}/{x}/{y}.png` 无需指定 `mapId`，服务端按地理区域自动选择最详细的数据源
- **多级自动加载**：低缩放显示全国底图，放大到具体城市自动切换至该城市高精度瓦片，跨层级无缝过渡
- **Overzoom 平滑放大**：超过数据源最大级别时自动放大显示，避免空白或重复渲染
- **双协议支持**：RESTful XYZ 瓦片接口 + OGC WMTS 1.0.0 标准协议
- **跨域开放**：内置 CORS，支持浏览器直连
- **自动扫描**：一键扫描目录、自动登记新增 MBTiles
- **零外部服务依赖**：仅依赖 Node.js 与 SQLite，瓦片直接从本地文件读取

**已验证数据源：**

| 数据源         | mapId        | 瓦片数 | 缩放级别 | 格式 | 范围（WGS84）                     |
| -------------- | ------------ | ------ | -------- | ---- | --------------------------------- |
| 中国           | `map-beb254` | 3550   | 2–9      | png  | 73.497, 3.593 ~ 135.103, 53.568   |
| 上海市         | `map-67f403` | 160211 | 2–17     | png  | 120.852, 30.677 ~ 122.242, 31.874 |
| 天津市         | `map-9fbc39` | 19150  | 2–15     | png  | 116.702, 38.554 ~ 118.059, 40.251 |
| 香港特别行政区 | `hongkong`   | 24337  | 2–17     | png  | 113.835, 22.154 ~ 114.442, 22.562 |
| 澳门特别行政区 | `map-b2f3db` | 1030   | 4–17     | png  | 113.528, 22.109 ~ 113.599, 22.217 |

> 数据源 `maxZoom` 最大值为 **17**（上海/香港/澳门），统一瓦片接口超过该级别后启用 overzoom 放大显示。

## 5. 配置说明

### 5.1 环境变量（.env）

| 变量          | 默认值               | 说明                                 |
| ------------- | -------------------- | ------------------------------------ |
| `PORT`        | `3000`               | 服务端口                             |
| `HOST`        | `0.0.0.0`            | 监听地址，`0.0.0.0` 表示所有网卡     |
| `MAPS_CONFIG` | `./config/maps.json` | 地图注册表路径                       |
| `CORS_ORIGIN` | `*`                  | 允许的跨域来源，生产建议改为具体域名 |

### 5.2 地图注册表（config/maps.json）

每份 MBTiles 对应一项配置：

```json
{
  "maps": [
    {
      "id": "macau",
      "name": "澳门特别行政区",
      "path": "D:/SGDownload/澳门特别行政区/澳门特别行政区_MBLites/澳门特别行政区.mbtiles",
      "description": "水经注下载 - 澳门离线卫星/影像地图"
    }
  ]
}
```

| 字段          | 必填 | 说明                                                      |
| ------------- | ---- | --------------------------------------------------------- |
| `id`          | 是   | 全局唯一标识，用于 URL 路径，建议使用 ASCII（如 `macau`） |
| `path`        | 是   | MBTiles 文件绝对路径，正反斜杠均可                        |
| `name`        | 否   | 显示名称，缺省时取文件名                                  |
| `description` | 否   | 描述信息                                                  |

> `format`、`bounds`、`minZoom`、`maxZoom`、`tileCount` 等元数据在服务启动时自动从 MBTiles 内部读取，**无需在配置中填写**。

## 6. 地图文件接入（文件上传）

本服务为**离线瓦片服务**，不提供 HTTP 文件上传通道；MBTiles 文件通过本地文件系统接入。提供两种方式：**手动登记** 与 **自动扫描**。

### 6.1 文件准备

水经注导出后，MBTiles 文件通常位于：

```
D:\SGDownload\<区域名>\<区域名>_MBLites\<区域名>.mbbtiles
```

> 注意：实际文件在 `_MBLites` 子目录下，扩展名为 `.mbtiles`。接入前请确认文件真实路径。

### 6.2 方式一：手动登记（推荐用于精确控制）

1. 将 MBTiles 文件放置到任意本地目录
2. 编辑 `config/maps.json`，新增一项：

```json
{
  "id": "shenzhen",
  "name": "深圳市",
  "path": "D:/SGDownload/深圳市/深圳市_MBLites/深圳市.mbtiles",
  "description": "水经注下载 - 深圳离线地图"
}
```

3. 重启服务：`npm start`

### 6.3 方式二：自动扫描（推荐用于批量接入）

使用 `scripts/scan-mbtiles.js` 递归扫描 `D:/SGDownload`，自动登记未配置的 MBTiles：

```bash
# 预览（不写入，推荐先执行）
npm run scan:dry

# 扫描并写入 config/maps.json
npm run scan

# 同时移除文件已不存在的配置项
npm run scan -- --prune
```

**脚本行为：**

- 递归查找所有 `*.mbtiles` 文件
- **按路径去重**：已存在的条目不会被重复添加，手动修改的 `id`/`name` 不会被覆盖
- 新增项自动生成：`id`（ASCII 优先，中文文件名回退为 `map-<短哈希>`）、`name`（文件名去除 `_MBLites`）、`description`
- 列出文件已丢失的条目，`--prune` 可清理

**扫描输出示例：**

```
扫描根目录 : D:/SGDownload
发现 .mbtiles 文件 : 2
配置已有 : 0
新增 : 2
  + [map-b2f3db] 澳门特别行政区
      -> D:/SGDownload/澳门特别行政区/澳门特别行政区_MBLites/澳门特别行政区.mbtiles
已更新配置 : config/maps.json
```

可通过环境变量覆盖扫描根目录与配置路径：

```bash
$env:SCAN_ROOT="D:/SGDownload"; $env:MAPS_CONFIG="./config/maps.json"; npm run scan
```

> 扫描完成后需**重启服务**才能生效；中文文件名自动生成的 `id` 为短哈希，如需更友好的标识可手动修改 `maps.json` 中的 `id` 字段。

## 7. API 接口手册

所有接口返回统一 JSON 结构：

```json
{ "success": true, "data": {} }
```

失败时：

```json
{ "success": false, "error": "错误描述" }
```

### 7.1 健康检查

`GET /health`

```bash
curl http://localhost:3000/health
```

```json
{ "success": true, "service": "offline-mbtiles-server", "maps": 5 }
```

### 7.2 服务根路径（URL 重写）

`GET /`

服务端通过 `res.sendFile()` 直接返回 `examples/openlayers.html` 内容，**浏览器地址栏保持 `http://localhost:3000/` 不变**，不出现 `examples` 路径。该方式对用户透明，不影响页面资源加载（页面内资源使用相对/绝对路径正常解析）。

### 7.3 服务端点清单

`GET /api`

返回所有可用端点的 JSON 清单，便于联调时自省：

```json
{
  "success": true,
  "message": "Offline MBTiles Map Server",
  "endpoints": {
    "health": "/health",
    "maps": "/api/maps",
    "unifiedTileTemplate": "/api/maps/tiles/{z}/{x}/{y}.png",
    "tileTemplate": "/api/maps/{mapId}/tiles/{z}/{x}/{y}.{format}",
    "wmtsCapabilities": "/wmts/{mapId}?service=WMTS&request=GetCapabilities",
    "wmtsTile": "/wmts/{mapId}?service=WMTS&request=GetTile&...",
    "examples": "/examples/"
  }
}
```

### 7.4 获取地图列表

`GET /api/maps`

返回所有已发布地图的完整元数据。

```bash
curl http://localhost:3000/api/maps
```

**响应：**

```json
{
  "success": true,
  "count": 2,
  "data": [
    {
      "id": "macau",
      "name": "澳门特别行政区",
      "description": "水经注下载 - 澳门离线卫星/影像地图",
      "format": "png",
      "bounds": { "west": 113.528181139, "south": 22.109150443, "east": 113.598862007, "north": 22.217043056 },
      "center": null,
      "minZoom": 4,
      "maxZoom": 17,
      "tileCount": 1030,
      "tileUrl": "/api/maps/macau/tiles/{z}/{x}/{y}.png",
      "wmtsUrl": "/wmts/macau",
      "metadata": { "name": "mbtiles", "format": "png", "bounds": "..." }
    }
  ]
}
```

**字段说明：**

| 字段                  | 说明                                          |
| --------------------- | --------------------------------------------- |
| `format`              | 瓦片图片格式（png/jpg/webp/pbf）              |
| `bounds`              | WGS84 经纬度边界 `{west, south, east, north}` |
| `minZoom` / `maxZoom` | 可用缩放级别范围                              |
| `tileCount`           | 瓦片总数                                      |
| `tileUrl`             | REST 瓦片地址模板（`{z}/{x}/{y}` 占位）       |
| `wmtsUrl`             | WMTS 入口地址                                 |

### 7.5 获取单个地图元数据

`GET /api/maps/:mapId`

```bash
curl http://localhost:3000/api/maps/hongkong
```

成功返回 `{ "success": true, "data": { ... } }`；地图不存在返回 `404`：

```json
{ "success": false, "error": "地图 \"xxx\" 不存在" }
```

### 7.6 统一瓦片接口（自动区域判断 · 推荐）

`GET /api/maps/tiles/:z/:x/:y.:format`

**核心特性：** 无需指定 `mapId`，服务端根据 `(z, x, y)` 自动计算瓦片中心经纬度，从所有地图中筛选包含该点的数据源，按 `maxZoom` 降序优先返回精度最高的瓦片。超过数据源最大级别时启用 **overzoom** 回退到父瓦片。

```bash
# 请求中国区域 z=5 瓦片，自动从"中国"地图返回
curl -o tile.png http://localhost:3000/api/maps/tiles/5/23/11.png

# 请求上海区域 z=14 瓦片，自动从"上海市"地图返回
curl -o tile.png http://localhost:3000/api/maps/tiles/14/13710/6660.png

# 请求 z=20（超过 maxZoom=17），overzoom 回退到 z=17 父瓦片
curl -o tile.png http://localhost:3000/api/maps/tiles/20/439047/214226.png
```

**响应头：**

```
Content-Type: image/png
Cache-Control: public, max-age=86400
X-Tile-Source: map-67f403              # 实际命中的数据源 mapId
X-Tile-Source-Name: %E4%B8%8A%E6%B5%B7%E5%B8%82  # 数据源名称（URL 编码）
X-Tile-Overzoom: true                  # 仅 overzoom 时存在
X-Tile-Source-Z: 17                    # 仅 overzoom 时存在，标识实际取瓦片的 z
```

**区域检测与 overzoom 逻辑：**

1. 由 `(z, x, y)` 计算瓦片中心经纬度（WGS84）
2. 收集所有 `bounds` 包含该点的地图，按 `maxZoom` 降序排列
3. 对每个候选地图：
   - `z` 在 `[minZoom, maxZoom]` 内：直接取瓦片
   - `z > maxZoom`：overzoom 回退到 `maxZoom` 处的父瓦片（`dz = z - maxZoom`，`scale = 2^dz`，父坐标 = `floor(子坐标 / scale)`）
   - 若该地图无此瓦片，降级到下一候选
4. 全部未命中返回 `404`

**参数校验：** 非整数坐标返回 `400`；负数缩放返回 `400`；坐标超出 `[0, 2^z)` 返回 `404`。

> 性能：实测单瓦片响应时间 1–12ms，远低于 200ms 阈值。

### 7.7 按 mapId 瓦片接口（REST · XYZ 坐标系）

`GET /api/maps/:mapId/tiles/:z/:x/:y.:format`

按指定 `mapId` 与 `z/x/y`（XYZ 规范，原点左上角）返回瓦片图片二进制。适用于明确知道数据源的场景。

```bash
# 下载澳门 z=12 x=3339 y=1788 的瓦片
curl -o tile.png http://localhost:3000/api/maps/map-b2f3db/tiles/12/3339/1788.png
```

**响应头：**

```
Content-Type: image/png
Cache-Control: public, max-age=86400
```

> 也支持不带扩展名的形式 `/:z/:x/:y`，`Content-Type` 仍按 MBTiles 内部格式自动判定。
>
> 坐标超出范围或瓦片不存在时返回 `404`；缩放级别越界返回 `404` 并提示。

### 7.8 接口汇总

| 接口                                                | 方法 | 说明                                        |
| --------------------------------------------------- | ---- | ------------------------------------------- |
| `/`                                                 | GET  | 根路径 URL 重写至 OpenLayers 示例页         |
| `/health`                                           | GET  | 健康检查                                    |
| `/api`                                              | GET  | 服务端点清单                                |
| `/api/maps`                                         | GET  | 地图列表                                    |
| `/api/maps/:mapId`                                  | GET  | 单图元数据                                  |
| `/api/maps/tiles/:z/:x/:y.:format`                  | GET  | **统一瓦片接口**（自动区域判断 + overzoom） |
| `/api/maps/:mapId/tiles/:z/:x/:y.:format`           | GET  | 按 mapId 的 XYZ 瓦片                        |
| `/wmts/:mapId?service=WMTS&request=GetCapabilities` | GET  | WMTS 能力文档                               |
| `/wmts/:mapId?service=WMTS&request=GetTile&...`     | GET  | WMTS 瓦片                                   |
| `/examples/`                                        | GET  | 前端示例静态页                              |

### 7.9 跨域（CORS）

服务全局启用 CORS：

- `Access-Control-Allow-Origin: *`（可经 `CORS_ORIGIN` 收窄）
- `Access-Control-Allow-Methods: GET, HEAD, OPTIONS`
- 预检 `OPTIONS` 请求自动返回 `204`

浏览器前端可直接 `fetch` 调用，无需代理。

## 8. WMTS 协议接入

WMTS（Web Map Tile Service）是 OGC 标准瓦片协议，便于 GIS 客户端（QGIS、ArcGIS、Cesium）标准化接入。

### 8.1 GetCapabilities（能力文档）

```bash
curl "http://localhost:3000/wmts/macau?service=WMTS&request=GetCapabilities"
```

返回 XML，包含：图层标识、WGS84 边界、瓦片格式、`TileMatrixSet`（EPSG:3857，含各层级矩阵参数）、`ResourceURL` 瓦片模板。

### 8.2 GetTile（获取瓦片）

```bash
curl "http://localhost:3000/wmts/macau?service=WMTS&request=GetTile&version=1.0.0&layer=macau&style=default&tilematrixset=EPSG3857&tilematrix=12&tilerow=1788&tilecol=3339" -o tile.png
```

**参数说明：**

| 参数            | 说明                           |
| --------------- | ------------------------------ |
| `service`       | 固定 `WMTS`                    |
| `request`       | `GetCapabilities` 或 `GetTile` |
| `layer`         | 图层 ID，即 `mapId`            |
| `style`         | 固定 `default`                 |
| `tilematrixset` | 固定 `EPSG3857`                |
| `tilematrix`    | 缩放级别 `z`                   |
| `tilerow`       | 行 `y`（XYZ 行号）             |
| `tilecol`       | 列 `x`                         |

> 参数名大小写不敏感。错误请求返回 OGC 标准 `ExceptionReport` XML。

### 8.3 在 QGIS 中接入

1. 菜单：`图层 → 添加图层 → 添加 WMTS 图层`
2. 新建连接，URL 填：`http://localhost:3000/wmts/hongkong?service=WMTS&request=GetCapabilities`
3. 连接后选择图层添加即可

## 9. 前端调用示例

### 9.1 OpenLayers（推荐 · 使用统一瓦片接口）

统一接口无需指定 `mapId`，服务端自动按区域选择数据源。关键点：**前端 source 必须设置 `maxZoom` 为数据源最大级别**（通过 `/api/maps` 获取），超过该级别由 OL 自动放大显示现有瓦片，避免服务端 overzoom 返回同一张父瓦片导致满屏重复。

```js
// 1. 拉取地图列表，计算数据源最大缩放层级
const res = await fetch('http://localhost:3000/api/maps')
const { data: maps } = await res.json()
const maxDataZoom = Math.max(...maps.map((m) => m.maxZoom)) // 当前 = 17

// 2. 初始化地图
const olMap = new ol.Map({
  target: 'map',
  view: new ol.View({ center: ol.proj.fromLonLat([121.4737, 31.2304]), zoom: 10 })
})

// 3. 加载统一瓦片图层（关键：maxZoom 限制防止 overzoom 重复渲染）
olMap.addLayer(
  new ol.layer.Tile({
    source: new ol.source.XYZ({
      url: 'http://localhost:3000/api/maps/tiles/{z}/{x}/{y}.png',
      maxZoom: maxDataZoom, // 超过则 OL 自动放大显示，不请求新瓦片
      crossOrigin: 'anonymous',
      transition: 200
    })
  })
)

// 4. 缩放级别实时显示（用 change:resolution 而非 change:zoom，确保动画过程实时更新）
olMap.getView().on('change:resolution', () => {
  const floatZoom = olMap.getView().getZoom()
  const tileZoom = Math.round(floatZoom)
  const info =
    tileZoom > maxDataZoom
      ? `${floatZoom.toFixed(2)} (数据 z=${maxDataZoom}, 放大 ${(floatZoom - maxDataZoom).toFixed(1)}级)`
      : `${floatZoom.toFixed(2)} (瓦片 z=${tileZoom})`
  document.getElementById('zoomInfo').innerHTML = info
})
```

完整示例：[examples/openlayers.html](http://localhost:3000/)（含加载状态指示、错误提示、最大层级提示）

### 9.2 Leaflet

```js
// 1. 拉取地图列表（CORS 已开放，可直接 fetch）
const res = await fetch('http://localhost:3000/api/maps')
const { data: maps } = await res.json()
const mapMeta = maps.find((m) => m.id === 'hongkong')

// 2. 初始化地图

  [south, west],

```

## 10. 实现逻辑说明

### 10.1 整体架构

```
┌──────────────────────────────────────────────────────────┐
│                    Express Server                        │
│  (CORS · URL 重写 · 请求日志 · 静态托管 · 路由 · 错误处理)│
├─────────┬──────────┬──────────────┬──────────────────────┤
│ /       │ /api/maps│ /api/maps/   │ /wmts                │
│ URL重写 │  元数据  │  tiles       │  WMTS Capabilities/  │
│ →示例页 │          │  统一瓦片    │  GetTile             │
├─────────┴──────────┴──────────────┴──────────────────────┤
│                   MBTilesManager                         │
│  Map<mapId, { db, metadata, bounds, ... }>              │
│  · 只读打开 SQLite                                       │
│  · 元数据/zoom 范围/瓦片数解析                           │
│  · TMS↔XYZ 行号转换                                      │
│  · getTileAuto：区域检测 + overzoom（统一接口核心）      │
├──────────────────────────────────────────────────────────┤
│            better-sqlite3 (readonly)                     │
│            ← config/maps.json 注册表                     │
└──────────────────────────────────────────────────────────┘
```

### 10.2 根路径 URL 重写

`app.get('/')` 使用 `res.sendFile()` 直接返回 `examples/openlayers.html`，而非 302 重定向。区别：

- **302 重定向**：浏览器地址栏会变成 `/examples/openlayers.html`，暴露内部路径
- **URL 重写（sendFile）**：浏览器地址栏保持 `/` 不变，对用户透明

页面内资源（CSS/JS/瓦片请求）使用绝对路径或 `window.location.origin` 拼接，不受 URL 重写影响。

### 10.3 统一瓦片接口与多级自动加载（核心）

统一接口 `GET /api/maps/tiles/{z}/{x}/{y}.png` 的核心是 `MBTilesManager.getTileAuto()`，实现多级地图数据自动加载：

**1. 区域检测**：由 `(z, x, y)` 计算瓦片中心经纬度（WGS84）：

```js
const n = Math.pow(2, z)
const lon = ((x + 0.5) / n) * 360 - 180
const lat = (Math.atan(Math.sinh(Math.PI * (1 - (2 * (y + 0.5)) / n))) * 180) / Math.PI
```

**2. 候选筛选**：遍历所有地图，收集 `bounds` 包含该点的地图，按 `maxZoom` 降序排列（优先高精度数据源）。例如上海区域 z=14，候选顺序为：上海市(maxZoom=17) > 中国(maxZoom=9，因 z>maxZoom 走 overzoom 但精度更低，仍会尝试)。

**3. 取瓦片**：对每个候选地图：

- `z ∈ [minZoom, maxZoom]`：直接取该瓦片
- `z > maxZoom`：overzoom 回退到 `maxZoom` 处父瓦片
- 若该地图无此瓦片（稀疏数据），降级到下一候选

**4. 前端配合**：前端 `ol.source.XYZ` 设置 `maxZoom = 数据源最大 maxZoom`，超过该级别由 OL 自动放大显示现有瓦片，**不请求新瓦片**。这避免了服务端 overzoom 对每个 (x,y) 都返回同一张父瓦片导致满屏重复渲染的问题。

### 10.4 Overzoom 机制

当请求 `z` 超过地图 `maxZoom` 时，回退到 `maxZoom` 处的父瓦片：

```js
const dz = z - map.maxZoom // 超出的层级数
const scale = Math.pow(2, dz) // 缩放倍数
const parentX = Math.floor(x / scale)
const parentY = Math.floor(y / scale)
// 从 map.maxZoom 层取 (parentX, parentY) 瓦片
```

响应头标识 overzoom 状态：

- `X-Tile-Overzoom: true`
- `X-Tile-Source-Z: <实际取瓦片的 z>`

> 服务端 overzoom 主要用于直接 API 调用场景；前端 OL/Leaflet 场景下应通过 source `maxZoom` 限制让客户端自行放大，体验更平滑。

### 10.5 MBTiles 文件结构

MBTiles 本质是一个 SQLite 数据库，核心两张表：

- **`metadata`**：键值对，存储 `name`/`format`/`bounds`/`type`/`version` 等元信息
- **`tiles`**：瓦片数据，字段 `zoom_level`、`tile_column`、`tile_row`、`tile_data`（BLOB）

服务启动时只读打开每个 MBTiles，读取 `metadata` 表与 `tiles` 表的 zoom 范围、瓦片总数，缓存于内存。

### 10.6 TMS 与 XYZ 坐标转换（关键）

MBTiles 内部按 **TMS** 规范存储（`tile_row` 原点在**左下角**），而 Leaflet / OpenLayers 等前端使用 **XYZ** 规范（原点在**左上角**）。两者行号需翻转：

```js
const tmsRow = Math.pow(2, zoom) - 1 - row
```

查询时将前端传入的 XYZ `y` 转为 TMS `tile_row` 再检索，确保瓦片正确对应。详见 `src/services/mbtilesManager.js`。

### 10.7 多源统一发布机制

- `config/maps.json` 是唯一数据源注册表
- `MBTilesManager` 启动时遍历注册表，用 `Map<id, mapInstance>` 持有所有已打开的只读 SQLite 连接
- 两种瓦片访问方式：
  - **统一接口**：`/api/maps/tiles/{z}/{x}/{y}.png`（自动区域判断，推荐）
  - **按 mapId**：`/api/maps/{mapId}/tiles/{z}/{x}/{y}.{format}`（明确数据源）
- 新增/移除地图：修改 `maps.json` → 重启服务（或调用 `mbtilesManager.reload()` 热重载）
- 单一进程、单一端口承载所有地图，避免多实例部署开销

### 10.8 WMTS Capabilities 生成

按 OGC WMTS 1.0.0 规范动态生成 XML，包含：

- `ServiceIdentification`：服务标识
- `Layer`：图层标题、标识、WGS84 边界、样式、格式
- `TileMatrixSet`：`EPSG:3857`，逐层级生成 `TileMatrix`（`ScaleDenominator`、`TopLeftCorner`、矩阵宽高）
- `ResourceURL`：瓦片模板，供客户端拼接

### 10.9 缓存与性能

- 瓦片响应头设置 `Cache-Control: public, max-age=86400`，浏览器/CDN 可缓存 1 天
- `better-sqlite3` 为同步绑定，配合 SQLite 自身页缓存，单瓦片查询延迟 1–12ms
- 只读打开，多请求并发安全
- 统一瓦片接口增加请求日志，记录数据源与耗时便于调试

### 10.10 生命周期管理

服务监听 `SIGINT` / `SIGTERM`，优雅关闭所有 SQLite 连接后再退出，避免文件句柄泄漏。`app._server` 与 `app._mbtilesManager` 暴露给测试与外部调用。

## 12. 常见问题

**Q：如何新增一份离线地图？**
A：将 `.mbtiles` 文件放入本地目录，运行 `npm run scan` 自动登记，或手动编辑 `config/maps.json` 后重启服务。新增的地图会自动被统一瓦片接口纳入区域检测候选。

**Q：为什么扫描生成的 id 是 `map-xxxxxx` 而非中文名？**
A：中文文件名无法生成 URL 安全的 ASCII id，故回退为短哈希保证唯一。可手动改 `maps.json` 中的 `id` 为任意 ASCII 标识（如 `macau`），重启生效。

**Q：统一瓦片接口与按 mapId 接口有何区别？该如何选择？**
A：

- **统一接口** `/api/maps/tiles/{z}/{x}/{y}.png`：服务端自动按地理区域选择最详细的数据源，前端无需关心 mapId。适用于多级地图混合展示场景（如先看全国再放大到城市）。
- **按 mapId 接口** `/api/maps/{mapId}/tiles/...`：明确指定数据源，适用于已知目标地图的场景（如 WMTS 接入、单图调试）。

**Q：放大超过最大级别后地图变模糊是正常现象吗？**
A：是。数据源最大级别为 z=17（上海/香港/澳门），超过后启用 overzoom 放大显示现有瓦片，图像会变模糊但不会空白。前端通过 source `maxZoom` 限制让 OL 自动放大，避免满屏重复渲染。

**Q：为什么放大到 z>17 后满屏都是同一张图重复？**
A：前端 `ol.source.XYZ` 未设置 `maxZoom`。未限制时 OL 会向服务端请求每个 (x,y) 瓦片，服务端 overzoom 对所有请求返回同一张父瓦片，导致重复。解决：设置 `maxZoom` 为数据源最大级别（通过 `/api/maps` 获取）。

**Q：缩放时状态栏的缩放级别为什么不更新？**
A：需监听 `change:resolution` 事件而非 `change:zoom`。OL 内部 resolution 是连续变化的，`change:zoom` 在动画过程中可能不触发，`change:resolution` 能确保实时更新。

**Q：是否支持矢量瓦片（pbf/mvt）？**
A：支持读取与返回（`Content-Type` 自动判定为 `application/x-protobuf`），但前端需自行配合矢量瓦片样式（如 Mapbox GL）渲染。

**Q：能否在生产环境开放公网访问？**
A：可以，但建议：将 `CORS_ORIGIN` 收窄为具体域名、置于反向代理（Nginx）之后、限制 `HOST` 监听地址，并做好瓦片缓存。

**Q：多个地图能否叠加显示？**
A：可以。前端按不同 `mapId` 创建多个瓦片图层叠加即可，注意 `minZoom/maxZoom` 与 `bounds` 的差异。统一接口本身已实现多源自动选择，通常无需手动叠加。

**Q：服务运行中修改了 `maps.json`，如何生效？**
A：需重启服务（`npm run dev` 模式下保存文件可触发热重启），或调用 `MBTilesManager.reload()` 热重载。

**Q：根路径访问 `http://localhost:3000/` 返回的是 JSON 还是 HTML？**
A：返回 HTML（OpenLayers 示例页）。服务端通过 `res.sendFile()` 进行 URL 重写，浏览器地址栏保持 `/` 不变。原 JSON 端点清单已迁移至 `GET /api`。
