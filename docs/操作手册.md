## 1. 项目概述

本服务将水经注下载并导出的 MBTiles 离线瓦片文件，统一发布为网络地图服务，供 Leaflet / OpenLayers / Cesium / QGIS 等前端或 GIS 客户端调用。

**核心特性：**

- **多源统一发布**：单个服务实例同时承载多份 MBTiles，通过 `mapId` 路径区分，无需每个文件单独部署
- **统一瓦片接口**：`/api/maps/tiles/{z}/{x}/{y}.png` 无需指定 `mapId`，服务端按缩放层级与地理区域自动选择数据源（z≤5 全球底图 → z6-9 国家级概览 → z10+ 省市详图）
- **多级自动加载**：低缩放显示全球底图，放大后自动切换至国家级、省市级高精度瓦片，跨层级无缝过渡
- **客户端平滑放大**：超过数据源最大级别时服务端返回 404，由前端（OpenLayers）自动拉伸已显示的祖先瓦片，无重复渲染
- **瓦片偏移矫正**：支持配置 `tileOffsetX` 修正下载工具导致的瓦片内容整体错列存储（如"中国"地图 +2 列偏移）
- **双协议支持**：RESTful XYZ 瓦片接口 + OGC WMTS 1.0.0 标准协议
- **跨域开放**：内置 CORS，支持浏览器直连
- **自动扫描**：一键扫描目录、自动登记新增 MBTiles
- **零外部服务依赖**：仅依赖 Node.js 与 SQLite，瓦片直接从本地文件读取

**已验证数据源（8 个）：**

| 数据源         | mapId              | 瓦片数 | 缩放级别 | 格式 | 范围（WGS84）                     | 备注                       |

| 全球           | `map-971f3cd08972` | 1364   | 1–5      | png  | -180, -86.13 ~ 180, 90            | 全球完整覆盖 z1-z5 底图    |

## 5. 配置说明

### 5.1 环境变量（.env）

| 变量          | 默认值               | 说明                                 |
| ------------- | -------------------- | ------------------------------------ |
| `PORT`        | `3000`               | 服务端口                             |
| `HOST`        | `0.0.0.0`            | 监听地址，`0.0.0.0` 表示所有网卡     |
| `MAPS_CONFIG` | `./config/maps.json` | 地图注册表路径                       |
| `CORS_ORIGIN` | `*`                  | 允许的跨域来源，生产建议改为具体域名 |

### 5.2 地图注册表（config/maps.json）

每份 MBTiles 对应一项配置：

```json
{
  "maps": [
    {
      "id": "macau",
      "name": "澳门特别行政区",
      "path": "D:/SGDownload/澳门特别行政区/澳门特别行政区_MBLites/澳门特别行政区.mbtiles",
      "description": "水经注下载 - 澳门离线卫星/影像地图"
    },
    {
      "id": "china",
      "name": "中国",
      "path": "D:/SGDownload/中国/中国_MBLites/中国.mbtiles",
      "bounds": { "west": 73.497551, "south": 3.593695, "east": 135.103684, "north": 53.568958 },
      "center": { "lon": 104.3006575, "lat": 28.5813265, "zoom": 4 },
      "minZoom": 1,
      "maxZoom": 9,
      "tileOffsetX": 2
    }
  ]
}
```

| 字段                  | 必填 | 说明                                                                                                                                            |
| --------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                  | 是   | 全局唯一标识，用于 URL 路径，建议使用 ASCII（如 `macau`）                                                                                       |
| `path`                | 是   | MBTiles 文件绝对路径，正反斜杠均可                                                                                                              |
| `name`                | 否   | 显示名称，缺省时取文件名                                                                                                                        |
| `description`         | 否   | 描述信息                                                                                                                                        |
| `bounds`              | 否   | 显式声明 WGS84 行政边界（优先于 mbtiles metadata 的下载框），支持 `[w,s,e,n]` 数组或 `{west,south,east,north}` 对象；直接决定统一接口的区域命中 |
| `center`              | 否   | 显式声明初始中心点 `{lon, lat, zoom}`（优先于 metadata）                                                                                        |
| `minZoom` / `maxZoom` | 否   | 显式声明缩放级别范围（优先于 metadata 的实际数据范围）                                                                                          |
| `tileOffsetX`         | 否   | 瓦片内容 X 方向网格偏移矫正量（默认 0），用于修正下载工具错列存储（详见 10.6）                                                                  |

> - `format`、`tileCount` 等元数据在服务启动时自动从 MBTiles 内部读取，无需填写。
> - **显式覆盖优先**：`bounds`/`center`/`minZoom`/`maxZoom` 配置后优先于 mbtiles 内部 metadata。推荐为每份地图显式声明精确行政 `bounds`（metadata 的下载框常含缓冲区/海洋），保证统一接口的区域命中与层级切换准确。
> - 空数据地图（`tileCount=0`）自动标记 `empty: true` 且 `minZoom/maxZoom` 置 null，前端可据此过滤。

## 6. 地图文件接入（文件上传）

本服务为**离线瓦片服务**，不提供 HTTP 文件上传通道；MBTiles 文件通过本地文件系统接入。提供两种方式：**手动登记** 与 **自动扫描**。

### 6.1 文件准备

水经注导出后，MBTiles 文件通常位于：

```
D:\SGDownload\<区域名>\<区域名>_MBLites\<区域名>.mbbtiles
```

> 注意：实际文件在 `_MBLites` 子目录下，扩展名为 `.mbtiles`。接入前请确认文件真实路径。

### 6.2 方式一：手动登记（推荐用于精确控制）

1. 将 MBTiles 文件放置到任意本地目录
2. 编辑 `config/maps.json`，新增一项：

```json
{
  "id": "shenzhen",
  "name": "深圳市",
  "path": "D:/SGDownload/深圳市/深圳市_MBLites/深圳市.mbtiles",
  "description": "水经注下载 - 深圳离线地图"
}
```

3. 重启服务：`npm start`

### 6.3 方式二：自动扫描（推荐用于批量接入）

使用 `scripts/scan-mbtiles.js` 递归扫描 `D:/SGDownload`，自动登记未配置的 MBTiles：

```bash
# 预览（不写入，推荐先执行）
npm run scan:dry

# 扫描并写入 config/maps.json
npm run scan

# 同时移除文件已不存在的配置项
npm run scan -- --prune
```

**脚本行为：**

- 递归查找所有 `*.mbtiles` 文件
- **按路径去重**：已存在的条目不会被重复添加，手动修改的 `id`/`name` 不会被覆盖
- 新增项自动生成：`id`（ASCII 优先，中文文件名回退为 `map-<短哈希>`）、`name`（文件名去除 `_MBLites`）、`description`
- 列出文件已丢失的条目，`--prune` 可清理

**扫描输出示例：**

```
扫描根目录 : D:/SGDownload
发现 .mbtiles 文件 : 2
配置已有 : 0
新增 : 2
  + [map-b2f3db] 澳门特别行政区
      -> D:/SGDownload/澳门特别行政区/澳门特别行政区_MBLites/澳门特别行政区.mbtiles
已更新配置 : config/maps.json
```

可通过环境变量覆盖扫描根目录与配置路径：

```bash
$env:SCAN_ROOT="D:/SGDownload"; $env:MAPS_CONFIG="./config/maps.json"; npm run scan
```

> 扫描完成后需**重启服务**才能生效；中文文件名自动生成的 `id` 为短哈希，如需更友好的标识可手动修改 `maps.json` 中的 `id` 字段。

### 7.6 统一瓦片接口（自动区域判断 · 推荐）

`GET /api/maps/tiles/:z/:x/:y.:format`

**核心特性：** 无需指定 `mapId`，服务端按**缩放层级策略**与地理区域自动选择数据源，保证每个缩放级别只有唯一权威数据源，避免多源混叠导致的重复渲染/错位：

- **z ≤ 全球图 maxZoom（z1-5）**：全球底图（完整覆盖，唯一数据源）
- **全球图 maxZoom < z ≤ 国家级 maxZoom（z6-9）**：优先国家级概览（如"中国"）；国家级稀疏缺失时回退省市级直接命中候选（消除两省交界空白）
- **z > 国家级 maxZoom（z10+）**：省市级地图，按 bounds 面积升序（更具体/内层优先，如上海 ⊂ 江苏时上海优先）
- **z > 某图 maxZoom**：不做服务端 overzoom，返回 404 由前端客户端拉伸放大（避免同一父瓦片重复渲染）
- **z < 某图 minZoom**：underzoom 回退到该图 minZoom 祖先瓦片（一对多覆盖，无重复）

```bash
# z=5 全球层级，自动从"全球"地图返回
curl -o tile.png http://localhost:3000/api/maps/tiles/5/26/12.png

# 上海区域 z=14，自动从"上海市"地图返回
curl -o tile.png http://localhost:3000/api/maps/tiles/14/13710/6660.png

# 请求 z=20（超过 maxZoom=17）→ 返回 404，由前端拉伸当前图像
curl -i http://localhost:3000/api/maps/tiles/20/439047/214226.png
```

**响应头：**

```
Content-Type: image/png
Cache-Control: no-cache, no-store, must-revalidate   # 统一接口禁长期缓存（返回内容随数据源策略变化）
X-Tile-Source: map-67f4036cacd9                      # 实际命中的数据源 mapId
X-Tile-Source-Name: %E4%B8%8A%E6%B5%B7%E5%B8%82      # 数据源名称（URL 编码）
X-Tile-Underzoom: true                               # 仅 underzoom（z<minZoom 祖先回退）时存在
X-Tile-Source-Z: 4                                   # 仅 underzoom 时存在，实际取瓦片的 z
X-Tile-Global-Fallback: true                         # 仅命中全球兜底时存在
```

**区域判定逻辑：**

1. `z ≤ 全球图 maxZoom`：直接返回全球底图瓦片
2. 收集所有与该瓦片矩形相交（`isTileIntersectsBounds`，非中心点判定——低层级瓦片单格可达 2.8°×2°，省界/海岸边缘瓦片中心常落在邻省 bounds 外或海域）的区域地图
3. 候选排序：直接命中（`minZoom ≤ z ≤ maxZoom`）优先于 underzoom；直接命中时国家级优先，省级按 bounds 面积升序
4. 按序逐一尝试取瓦片，首个命中者返回（国家级稀疏缺失由省市级无缝衔接）
5. 全部未命中返回 `404`

**参数校验：** 非整数坐标返回 `400`；负数缩放返回 `400`；坐标超出 `[0, 2^z)` 返回 `404`。

> 性能：实测单瓦片响应时间 1–12ms，远低于 200ms 阈值。

### 7.7 按 mapId 瓦片接口（REST · XYZ 坐标系）

`GET /api/maps/:mapId/tiles/:z/:x/:y.:format`

按指定 `mapId` 与 `z/x/y`（XYZ 规范，原点左上角）返回瓦片图片二进制。适用于明确知道数据源的场景。

```bash
# 下载澳门 z=12 x=3339 y=1788 的瓦片
curl -o tile.png http://localhost:3000/api/maps/map-b2f3db/tiles/12/3339/1788.png
```

**响应头：**

```
Content-Type: image/png
Cache-Control: public, max-age=86400
```

> 也支持不带扩展名的形式 `/:z/:x/:y`，`Content-Type` 仍按 MBTiles 内部格式自动判定。
>
> 坐标超出范围或瓦片不存在时返回 `404`；缩放级别越界返回 `404` 并提示。

## 8. WMTS 协议接入

WMTS（Web Map Tile Service）是 OGC 标准瓦片协议，便于 GIS 客户端（QGIS、ArcGIS、Cesium）标准化接入。

### 8.1 GetCapabilities（能力文档）

```bash
curl "http://localhost:3000/wmts/macau?service=WMTS&request=GetCapabilities"
```

返回 XML，包含：图层标识、WGS84 边界、瓦片格式、`TileMatrixSet`（EPSG:3857，含各层级矩阵参数）、`ResourceURL` 瓦片模板。

### 8.2 GetTile（获取瓦片）

```bash
curl "http://localhost:3000/wmts/macau?service=WMTS&request=GetTile&version=1.0.0&layer=macau&style=default&tilematrixset=EPSG3857&tilematrix=12&tilerow=1788&tilecol=3339" -o tile.png
```

**参数说明：**

| 参数            | 说明                           |
| --------------- | ------------------------------ |
| `service`       | 固定 `WMTS`                    |
| `request`       | `GetCapabilities` 或 `GetTile` |
| `layer`         | 图层 ID，即 `mapId`            |
| `style`         | 固定 `default`                 |
| `tilematrixset` | 固定 `EPSG3857`                |
| `tilematrix`    | 缩放级别 `z`                   |
| `tilerow`       | 行 `y`（XYZ 行号）             |
| `tilecol`       | 列 `x`                         |

> 参数名大小写不敏感。错误请求返回 OGC 标准 `ExceptionReport` XML。

### 8.3 在 QGIS 中接入

1. 菜单：`图层 → 添加图层 → 添加 WMTS 图层`
2. 新建连接，URL 填：`http://localhost:3000/wmts/hongkong?service=WMTS&request=GetCapabilities`
3. 连接后选择图层添加即可

## 9. 前端调用示例

### 9.1 OpenLayers（推荐 · 使用统一瓦片接口 + 双图层架构）

统一接口无需指定 `mapId`，服务端自动按层级与区域选择数据源。`examples/openlayers.html` 采用**双图层架构**，是本服务的参考实现：

- **baseLayer**（全球底图）：`minZoom=1, maxZoom=全球图maxZoom(5)`，`opaque: true`
- **detailLayer**（区域详图）：`minZoom=6, maxZoom=数据源最大maxZoom(17)`，`opaque: false`
- 图层切换：在 `[baseMaxZoom-0.5, baseMaxZoom+1.5]` 区间用 smootherstep 曲线渐变 detail 层透明度，透明度为 0 时隐藏 detail 层（避免 OL 为不可见层加载瓦片）
- **层级闸门**：`tileLoadFunction` 内拦截超出当前区域数据层级的请求（直接置 ERROR 不发请求），效果等同动态 `source.maxZoom` 但不换源
- **祖先链补载**：瓦片 404/被拦截时自动把祖先瓦片拉进 tileCache，OL 渲染器用已缓存祖先瓦片拉伸填充，缩放跳变不露底图海洋白块
- **URL 定位参数**：`?lon=&lat=&zoom=` 直接定位初始视图（如 `http://localhost:3000/?lon=121.47&lat=31.23&zoom=8`），便于分享链接与自动化验证
- **缓存版本号**：瓦片 URL 带 `?v=8` 版本号——统一接口禁止长期缓存，但版本号可兜底跳过浏览器旧缓存（服务端数据源策略变化后升版本号）

```js
// 简化版接入（单图层场景）
const res = await fetch('http://localhost:3000/api/maps')
const { data: maps } = await res.json()
const maxDataZoom = Math.max(...maps.filter((m) => !m.empty && m.maxZoom).map((m) => m.maxZoom)) // 当前 = 17

const olMap = new ol.Map({
  target: 'map',
  view: new ol.View({ center: ol.proj.fromLonLat([121.4737, 31.2304]), zoom: 10 })
})

olMap.addLayer(
  new ol.layer.Tile({
    source: new ol.source.XYZ({
      url: 'http://localhost:3000/api/maps/tiles/{z}/{x}/{y}.png?v=8',
      maxZoom: maxDataZoom, // 关键：超过则 OL 不请求新瓦片，自动放大显示现有瓦片
      crossOrigin: 'anonymous',
      transition: 200
    })
  })
)
```

完整示例：[examples/openlayers.html](http://localhost:3000/)（含双图层渐变、加载状态指示、数据源信息面板、所在区域识别、单击进入区域数据层级）

## 10. 实现逻辑说明

### 10.1 整体架构

```
┌──────────────────────────────────────────────────────────┐
│                    Express Server                        │
│  (CORS · URL 重写 · 请求日志 · 静态托管 · 路由 · 错误处理)│
├─────────┬──────────┬──────────────┬──────────────────────┤
│ /       │ /api/maps│ /api/maps/   │ /wmts                │
│ URL重写 │  元数据  │  tiles       │  WMTS Capabilities/  │
│ →示例页 │          │  统一瓦片    │  GetTile             │
├─────────┴──────────┴──────────────┴──────────────────────┤
│                   MBTilesManager                         │
│  Map<mapId, { db, metadata, bounds, ... }>              │
│  · 只读打开 SQLite                                       │
│  · 元数据/zoom 范围/瓦片数解析                           │
│  · TMS↔XYZ 行号转换                                      │
│  · getTileAuto：层级策略 + 区域检测（统一接口核心）      │
├──────────────────────────────────────────────────────────┤
│            better-sqlite3 (readonly)                     │
│            ← config/maps.json 注册表                     │
└──────────────────────────────────────────────────────────┘
```

### 10.2 根路径 URL 重写

`app.get('/')` 使用 `res.sendFile()` 直接返回 `examples/openlayers.html`，而非 302 重定向。区别：

- **302 重定向**：浏览器地址栏会变成 `/examples/openlayers.html`，暴露内部路径
- **URL 重写（sendFile）**：浏览器地址栏保持 `/` 不变，对用户透明

页面内资源（CSS/JS/瓦片请求）使用绝对路径或 `window.location.origin` 拼接，不受 URL 重写影响。

### 10.3 统一瓦片接口与层级数据源策略（核心）

统一接口 `GET /api/maps/tiles/{z}/{x}/{y}.png` 的核心是 `MBTilesManager.getTileAuto()`。设计目标：**每个缩放级别只对应一个权威数据源**，避免"不同数据源在同一 z 混叠"导致的双重图层/错位（曾出现"南京重复出现"问题）：

**1. 全球层级（z ≤ 全球图 maxZoom，当前 z1-5）**：全球底图覆盖完整，直接返回，不与任何区域地图混叠。

**2. 国家级层级（全球图 maxZoom < z ≤ 国家级 maxZoom，当前 z6-9）**：优先国家级概览图（按 bounds 面积最大自动识别，如"中国"）；国家级稀疏缺失的瓦片（两省交界、省界缓冲区）回退省市级直接命中候选无缝衔接。

**3. 省市级层级（z > 国家级 maxZoom，当前 z10+）**：省市级地图按 bounds 面积**升序**（更具体/内层优先），正确处理嵌套（上海 ⊂ 江苏时上海内部用上海、外部用江苏），交界缓冲瓦片由首个命中来源衔接。

**4. 区域候选判定用"瓦片矩形与 bounds 相交"**（`isTileIntersectsBounds`），而非中心点命中——低层级瓦片单格可达 2.8°×2°，省界/海岸线边缘瓦片"覆盖交界陆地但中心落在邻省 bounds 外或海域"会被中心点判断错误排除，导致 404 空白。

**5. 逐候选回退**：直接命中候选（国家级在前 → 省市面积升序）按序逐一尝试，首个命中者返回；每个瓦片仅由一个来源提供，无同格双源混叠。

**6. 前端配合**：前端 `ol.source.XYZ` 设置 `maxZoom = 数据源最大 maxZoom`，超过该级别由 OL 自动放大显示现有瓦片，**不请求新瓦片**（双图层架构见 9.1）。

### 10.4 Overzoom / Underzoom 机制

**服务端不做 overzoom**（z > map.maxZoom 时返回 404）。原因：服务端 overzoom 会把同一张父瓦片返回给多个子瓦片请求，OL 将整张父图绘制进每个子格子 → 同一图像被重复渲染/错位（满屏重复）。正确做法是返回 404，由前端 OL 对"当前已显示的图像"做客户端放大（`useInterimTilesOnError` 拉伸祖先瓦片），天然无重复、无错位。

**underzoom 回退仍保留**（z < map.minZoom 时）：

```js
const dz = map.minZoom - zoom // 差的层级数
const scale = Math.pow(2, dz) // 缩放倍数
fetchZ = map.minZoom // 回退到该图 minZoom 层
fetchX = Math.floor(x * scale) // 祖先瓦片坐标
fetchY = Math.floor(y * scale)
```

祖先瓦片**一对多覆盖**（一张父图对应多个子格请求属同一张图的不同区域裁切），无重复渲染问题。响应头标识：`X-Tile-Underzoom: true` + `X-Tile-Source-Z: <实际取瓦片的 z>`。

### 10.5 MBTiles 文件结构

MBTiles 本质是一个 SQLite 数据库，核心两张表：

- **`metadata`**：键值对，存储 `name`/`format`/`bounds`/`type`/`version` 等元信息
- **`tiles`**：瓦片数据，字段 `zoom_level`、`tile_column`、`tile_row`、`tile_data`（BLOB）

服务启动时只读打开每个 MBTiles，读取 `metadata` 表与 `tiles` 表的 zoom 范围、瓦片总数，缓存于内存。

### 10.6 TMS/XYZ 坐标转换与瓦片偏移矫正（关键）

MBTiles 内部按 **TMS** 规范存储（`tile_row` 原点在**左下角**），而 Leaflet / OpenLayers 等前端使用 **XYZ** 规范（原点在**左上角**）。两者行号需翻转：

```js
const tmsRow = Math.pow(2, zoom) - 1 - row
```

查询时将前端传入的 XYZ `y` 转为 TMS `tile_row` 再检索，确保瓦片正确对应。详见 `src/services/mbtilesManager.js`。

**瓦片内容网格偏移矫正（`tileOffsetX`）：**

部分下载工具生成的 MBTiles 存在瓦片内容整体错列存储——存储列 `X` 的瓦片图像实为标准 XYZ 网格列 `X + tileOffsetX` 的地理内容（y 方向无偏移）。本项目的"中国"地图实测偏移 +2 列（z1-9 全层级全国一致），曾导致 z6-9 视图中地理特征整体偏西 2 格、与省级地图拼接时同一特征重复出现且错位。

服务端读取时自动矫正（`getTile` 与 `_fetchTile` 的 direct/underzoom 路径统一应用）：

```js
// maps.json 声明："tileOffsetX": 2
const fetchColumn = x - (map.tileOffsetX || 0) // 读取列 X-2 的存储瓦片
```

> **如何判别新接入地图是否存在偏移**：将同区域两份地图（或该图与全球底图）同坐标瓦片做像素相关性对比，若存储 `(z,X,Y)` 与参照图 `(z,X±n,Y)` 相关性显著高于同坐标（r>0.95），即存在 n 列偏移，在 `maps.json` 中为该图配置 `"tileOffsetX": n`。

### 10.7 多源统一发布机制

- `config/maps.json` 是唯一数据源注册表
- `MBTilesManager` 启动时遍历注册表，用 `Map<id, mapInstance>` 持有所有已打开的只读 SQLite 连接
- 两种瓦片访问方式：
  - **统一接口**：`/api/maps/tiles/{z}/{x}/{y}.png`（自动区域判断，推荐）
  - **按 mapId**：`/api/maps/{mapId}/tiles/{z}/{x}/{y}.{format}`（明确数据源）
- 新增/移除地图：修改 `maps.json` → 重启服务（或调用 `mbtilesManager.reload()` 热重载）
- 单一进程、单一端口承载所有地图，避免多实例部署开销

### 10.8 WMTS Capabilities 生成

按 OGC WMTS 1.0.0 规范动态生成 XML，包含：

- `ServiceIdentification`：服务标识
- `Layer`：图层标题、标识、WGS84 边界、样式、格式
- `TileMatrixSet`：`EPSG:3857`，逐层级生成 `TileMatrix`（`ScaleDenominator`、`TopLeftCorner`、矩阵宽高）
- `ResourceURL`：瓦片模板，供客户端拼接

### 10.9 缓存与性能

- **统一瓦片接口禁长期缓存**：响应头 `Cache-Control: no-cache, no-store, must-revalidate`——同一 URL（z/x/y）的返回内容会随服务端数据源选择策略变化，长期缓存会导致"修复不生效"（浏览器仍命中旧瓦片）。前端瓦片 URL 附加版本号 `?v=N`（当前 v=8），策略变化后升版本号兜底跳过旧缓存；OL 自身内存缓存已足够性能
- **按 mapId 瓦片接口与 WMTS 可长期缓存**：`Cache-Control: public, max-age=86400`（URL 唯一确定数据源，内容不变）
- `better-sqlite3` 为同步绑定，配合 SQLite 自身页缓存，单瓦片查询延迟 1–12ms
- 只读打开，多请求并发安全
- 统一瓦片接口增加请求日志，记录数据源与耗时便于调试

### 10.10 生命周期管理

服务监听 `SIGINT` / `SIGTERM`，优雅关闭所有 SQLite 连接后再退出，避免文件句柄泄漏。`app._server` 与 `app._mbtilesManager` 暴露给测试与外部调用。

### 11.2 故障排查

| 现象                         | 可能原因                   | 处理                                                                                                         |
| ---------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 启动报「MBTiles 文件不存在」 | `maps.json` 中 `path` 错误 | 确认真实路径（注意 `_MBLites` 子目录）                                                                       |
| 瓦片返回 404                 | 缩放级别越界或该坐标无瓦片 | 用 `/api/maps/:mapId` 核对 `minZoom/maxZoom` 与 `bounds`；z>数据源 maxZoom 返回 404 属预期（前端客户端放大） |
| 统一接口某区域返回 404       | 该区域无任何地图覆盖       | 检查 `bounds` 是否与目标瓦片矩形相交；用 `find-tiles.js` 验证                                                |
| 前端地图空白                 | 跨域被拦截或地址错误       | 检查 `CORS_ORIGIN`；确认 `tileUrl` 模板                                                                      |
| 放大后满屏同一张图重复       | 前端 source 未限制 maxZoom | 设置 `maxZoom` 为数据源最大级别，让 OL 自动放大显示                                                          |
| 同一地理特征重复出现且错位   | 某地图瓦片内容网格偏移     | 按本手册 10.6 方法判别偏移量，在 `maps.json` 配置 `tileOffsetX` 矫正                                         |
| 服务端已修复但前端"不生效"   | 浏览器缓存旧瓦片           | 统一接口已禁长缓存；若仍命中旧缓存，升级前端 URL 版本号 `?v=N`                                               |
| 缩放级别显示不实时           | 用了 `change:zoom` 事件    | 改用 `change:resolution` 事件，动画过程也能实时更新                                                          |
| `better-sqlite3` 安装失败    | 缺构建工具                 | Windows 安装 `windows-build-tools` 或换 Node LTS                                                             |
| 扫描不到文件                 | 根目录错误                 | 用 `SCAN_ROOT` 环境变量指定正确目录                                                                          |
| 端口 3000 被占用             | 旧进程未退出               | `netstat -ano \| findstr :3000` 查 PID 后 `taskkill /F /PID <pid>`                                           |
| 瓦片上下颠倒                 | TMS/XYZ 转换异常           | 确认未误改 `mbtilesManager.js` 的行号翻转逻辑                                                                |

### 11.3 验证服务可用性


## 12. 常见问题

**Q：如何新增一份离线地图？**
A：将 `.mbtiles` 文件放入本地目录，运行 `npm run scan` 自动登记，或手动编辑 `config/maps.json` 后重启服务。新增的地图会自动被统一瓦片接口纳入区域检测候选。

**Q：为什么扫描生成的 id 是 `map-xxxxxx` 而非中文名？**
A：中文文件名无法生成 URL 安全的 ASCII id，故回退为短哈希保证唯一。可手动改 `maps.json` 中的 `id` 为任意 ASCII 标识（如 `macau`），重启生效。

**Q：统一瓦片接口与按 mapId 接口有何区别？该如何选择？**
A：

- **统一接口** `/api/maps/tiles/{z}/{x}/{y}.png`：服务端按缩放层级与地理区域自动选择数据源（z≤5 全球 → z6-9 国家级 → z10+ 省市），前端无需关心 mapId。适用于多级地图混合展示场景（如先看全球再放大到城市）。
- **按 mapId 接口** `/api/maps/{mapId}/tiles/...`：明确指定数据源，适用于已知目标地图的场景（如 WMTS 接入、单图调试）。

**Q：放大超过最大级别后地图变模糊是正常现象吗？**
A：是。数据源最大级别为 z=17（上海/香港/澳门），超过后服务端返回 404，由前端 OL 自动拉伸已显示的祖先瓦片放大显示（客户端放大），图像会变模糊但不会空白、不会重复。

**Q：为什么放大到 z>17 后满屏都是同一张图重复？**
A：前端 `ol.source.XYZ` 未设置 `maxZoom`。未限制时 OL 会向服务端请求每个 (x,y) 瓦片。解决：设置 `maxZoom` 为数据源最大级别（通过 `/api/maps` 获取）。注意：服务端已不做 overzoom（超层级一律 404），重复渲染只会来自前端未限制 maxZoom 或多数据源同 z 混叠。

**Q：画面中同一城市/河流出现两次，且两个位置对不上？**
A：这是"瓦片内容网格偏移"的典型症状——某地图存储列 X 的瓦片内容实为标准网格列 X±n 的地理内容，该地图上的特征被画在偏移位置，与正确位置的另一数据源瓦片拼在一起就出现"重复+错位"。判别与矫正方法见 10.6（配置 `tileOffsetX`）。

**Q：服务端修改了数据源选择逻辑/矫正配置，前端刷新后看到的还是旧瓦片？**
A：统一瓦片接口已设置 `no-cache, no-store, must-revalidate` 禁止长期缓存。若浏览器（或中间代理）仍命中旧缓存，将 `openlayers.html` 中瓦片 URL 的版本号 `?v=8` 升级为 `?v=9` 即可强制跳过。

**Q：缩放时状态栏的缩放级别为什么不更新？**
A：需监听 `change:resolution` 事件而非 `change:zoom`。OL 内部 resolution 是连续变化的，`change:zoom` 在动画过程中可能不触发，`change:resolution` 能确保实时更新。

**Q：是否支持矢量瓦片（pbf/mvt）？**
A：支持读取与返回（`Content-Type` 自动判定为 `application/x-protobuf`），但前端需自行配合矢量瓦片样式（如 Mapbox GL）渲染。

**Q：能否在生产环境开放公网访问？**
A：可以，但建议：将 `CORS_ORIGIN` 收窄为具体域名、置于反向代理（Nginx）之后、限制 `HOST` 监听地址，并做好瓦片缓存。

**Q：多个地图能否叠加显示？**
A：可以。前端按不同 `mapId` 创建多个瓦片图层叠加即可，注意 `minZoom/maxZoom` 与 `bounds` 的差异。统一接口本身已实现多源自动选择，通常无需手动叠加。

**Q：服务运行中修改了 `maps.json`，如何生效？**
A：需重启服务（`npm run dev` 模式下保存文件可触发热重启），或调用 `MBTilesManager.reload()` 热重载。

**Q：根路径访问 `http://localhost:3000/` 返回的是 JSON 还是 HTML？**
A：返回 HTML（OpenLayers 示例页）。服务端通过 `res.sendFile()` 进行 URL 重写，浏览器地址栏保持 `/` 不变。原 JSON 端点清单已迁移至 `GET /api`。
